For step 5, the three Waiting entries the 40 ft card is counting:
USE MoffatBayMarinaDB;

SELECT w.waitListID, w.customerID, c.email, sz.sizeFt, w.status, w.timeJoined
FROM WaitList w
JOIN SlipSize sz ON sz.slipSizeID = w.slipSizeID
JOIN Customer c  ON c.customerID  = w.customerID
WHERE w.status IN ('Waiting', 'Offered')
ORDER BY sz.sizeFt, w.timeJoined;
For step 6, the slip counts the estimate's N comes from:
USE MoffatBayMarinaDB;

SELECT sz.sizeFt, s.slipStatus, COUNT(*) AS slips
FROM Slip s
JOIN SlipSize sz ON sz.slipSizeID = s.slipSizeID
GROUP BY sz.sizeFt, s.slipStatus
ORDER BY sz.sizeFt;

For step 3, the line in the order the page should show it:
USE MoffatBayMarinaDB;

SELECT c.email, w.status, w.timeJoined,
       (SELECT COUNT(*)
          FROM WaitList a
         WHERE a.slipSizeID = w.slipSizeID
           AND a.status IN ('Waiting', 'Offered')
           AND (a.timeJoined < w.timeJoined
                OR (a.timeJoined = w.timeJoined AND a.waitListID < w.waitListID))
       ) AS peopleAhead
FROM WaitList w
JOIN SlipSize sz ON sz.slipSizeID = w.slipSizeID
JOIN Customer c  ON c.customerID  = w.customerID
WHERE sz.sizeFt = 40
  AND w.status IN ('Waiting', 'Offered')
ORDER BY w.timeJoined;

Comments

Developer (Miguel)
All five steps passed.
Two customers rather than one on purpose. Position 1 with 0 ahead is exactly what a broken query returns for everybody, so Rosa on her own proves nothing - Nadia at position 3 with 2 ahead is what actually shows the ordering works. Step 4 is the other half of it: a Fulfilled entry has to be invisible here and must not be counted in the public number either.
peopleAhead is counted in SQL rather than by loading the line into Java, so no other customer's row is ever read into memory to work out where you stand. The customer ID comes from the session and is never read off the request, so there is no parameter to edit to see someone else's place.
