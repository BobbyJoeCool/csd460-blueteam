Comments

Developer (Miguel)
All eight steps passed. The signed-in state is handled entirely by the shared header include, so it appeared correctly on the landing page and the About Us page without either page containing its own session check. The display name arrives from the session already formatted as first name plus last initial, so no page has to build it.

Step 7 is worth flagging for the team rather than counted as a failure. Pressing Back after logout shows a cached copy of the signed-in page. The session really is gone, as step 8 proves, but on a shared computer the next person could still glimpse the previous user's page from history. Adding no-cache response headers to pages that require a login would close that gap, and it is worth considering before the site is handed over.

The landing page hero button also changes behaviour once signed in. It links straight to the reservations page instead of opening the sign in popup, which removes the loop where a signed-in customer was still being asked to log in.
Peer Tester (Sara)

While the session was not active (and this was confirmed upon reloading the page), it would be preferable if no personal information was displayed.

Comments

Developer (Miguel)
All ten steps passed. Step 4 is the important one. The failure message for an email that has no account is identical to the message for a real account with a wrong password, so the popup cannot be used to work out which email addresses are registered.

This behaviour is the result of a change made during this module. The message originally counted down the remaining attempts, showing "2 more failed attempts will lock this account." That was replaced because a countdown can only ever appear for an address that exists, so watching for it confirmed valid accounts and undid the purpose of the single generic error message. The fixed message gives a real user the same useful warning while telling an attacker nothing.

Attempts against an email with no account are deliberately not recorded anywhere, since there is no account row to attach a count to. That is worth knowing when repeating this test, because step 4 does not affect the running failure count used by steps 3, 5 and 6.
